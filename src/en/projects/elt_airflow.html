This project brings together a complete Data Engineering workflow built around the ELT (Extract, Load, Transform) paradigm. What sets this architecture apart is its end-to-end integration with a proprietary Data Source (built in the Hyper-Rent project), demonstrating command of both the software engineering that serves the data and the analytical infrastructure that consumes it.

Isolated Networks Architecture (Docker)

To simulate a real and secure production environment, the infrastructure was split into two distinct Docker networks that communicate through a proxy:

  • Data Source Network: Hosts the REST API (Node.js/Express) protected by an Nginx acting as a Forward Proxy.
  • Data Pipeline Network (Airflow): Contains the extraction workers, the analytical database, and the transformation engine.

The ELT Flow

1. Extract (Python)

Apache Airflow orchestrates a Python script that calls the secured API endpoint (http://localhost/api/admin/cars?apikey=). Using API keys ensures that pre-analyzed data is extracted in a governed way, respecting the data contracts of the source application.

2. Load (PostgreSQL)

The raw data collected in JSON format is loaded directly, without heavy in-memory manipulation, into the Raw/Staging layer of an isolated PostgreSQL database. This ensures the Data Lake/Warehouse keeps an uncorrupted history of what was ingested.

3. Transform (dbt)

With the data already in PostgreSQL, Airflow triggers the dbt (Data Build Tool) models. dbt performs the heavy lifting of cleaning, standardization, and dimensional structuring using Postgres' own native SQL engine. This completes the transition from raw data to an analytical model ready for consumption (Views/Marts).
