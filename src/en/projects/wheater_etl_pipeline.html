The Weather ETL Project was built to automate the continuous collection of weather data from multiple cities and consolidate it in a relational database. It is a complete ETL (Extract, Transform, Load) pipeline, natively encapsulated in Docker containers, which removes the need to install any local dependencies other than the virtualization engine itself.

Pipeline Mechanics

  • Extract: The script reads a predefined list of cities from a CSV file and consumes real-time data through the WeatherAPI.
  • Transform: Using the Pandas library, the JSON data is cleaned and standardized. Column names are adjusted to SQL conventions and a collection timestamp is injected into each record to ensure time traceability.
  • Load: The processed data is loaded and appended to the final table in a PostgreSQL database.

Technical Details and Infrastructure

The project was designed with resilience and service independence in mind:

  • Python: The core engine for all request logic (requests) and data modeling (Pandas).
  • Docker Compose: Orchestrates the joint startup of the application (script) and the database as isolated services on the same network.
  • PostgreSQL: The storage layer that retains a reliable weather history for future analysis.
  • Healthchecks (Docker): A crucial safeguard. The Python script is set to wait until the PostgreSQL container reports a "Healthy" status (fully ready to accept connections), preventing crashes and timeout errors at startup.

How to Run Locally

1. Create a .env file at the project root with the following environment variables:

{% codeblock "bash" %} WEATHER_API_KEY=your_key_here DATABASE_STRING=postgresql://postgres:vini@postgres:5432/etl {% endcodeblock %}
Note: You can generate the API key for free on the WeatherAPI portal. The database connection string is already set up for the Docker network, but if you change credentials (such as the password), make sure to reflect those changes in the docker_compose.yml file.

2. With the .env file configured, bring up the full environment by running:

{% codeblock "bash" %} docker compose -f Docker/docker_compose.yml up --build {% endcodeblock %}
