Have you ever wondered how to synchronize two tables in a database? At first, the standard approach is to write multiple IF EXISTS, UPDATE, and INSERT statements. It works, but the query becomes massive and performance won't be optimal.

That might be the right time to get to know the MERGE statement. In this article, I will detail how it works, when it should be your go-to option in ELT (Extract, Load, Transform) processes, and what precautions to take in high-concurrency environments.

1.

What is MERGE and what does it replace?

The MERGE statement (frequently called an "Upsert") combines INSERT, UPDATE, and DELETE operations into a single atomic transaction. It compares a Target table with a Source table through a join condition (JOIN).

It replaces the traditional anti-pattern of writing separate, sequential instructions. Instead of the database engine scanning the tables multiple times to update what exists and insert what is new, MERGE processes the logic in a single pass.

2. Pros, Cons, and Where It Works

Where Does It Work?

The MERGE syntax is an ANSI SQL standard natively supported by Microsoft SQL Server (T-SQL), Oracle, and PostgreSQL (starting from version 15).

Advantages (Pros)

  • Batch Performance: Excellent for data loading processes (ETL/ELT), moving data from a Staging layer to a Gold/Production layer, for example.
  • Atomicity: If an error occurs while inserting a single record, the entire operation fails, preventing you from ending up with partially updated data.
  • Clean Code: The syntax is extremely readable and declarative.

Disadvantages (Cons and Warnings)

  • Concurrency (Race Conditions): In OLTP systems with many simultaneous transactions, MERGE can generate concurrency issues. If two sessions try to run a MERGE on the same table simultaneously, you could end up with duplicate keys.
  • Deadlocks: Because it performs everything at once, it requires heavier database locks.
  • The Workaround: If you need to use it in a concurrent environment, use the HOLDLOCK or NOLOCK hint on the target table to serialize access.

3. Practical Scenario: Synchronizing Staging and Production

Let's dive into the code. Imagine we have a daily routine that receives a product inventory. We need to update the Production table (Target) based on data that arrived in the temporary table (Source).

Step 1: Creating the Environment and Populating Data

{% codeblock "sql" %} CREATE SCHEMA stg; GO CREATE TABLE dbo.Target_ProductInventory ( ProductID INT PRIMARY KEY, ProductName VARCHAR(100), Quantity INT, LastUpdated DATETIME ); CREATE TABLE stg.Source_ProductInventory ( ProductID INT PRIMARY KEY, ProductName VARCHAR(100), Quantity INT, LastUpdated DATETIME ); INSERT INTO dbo.Target_ProductInventory (ProductID, ProductName, Quantity, LastUpdated) VALUES (1, 'Notebook ThinkPad', 50, '2026-08-01 10:00:00'), (2, 'Mouse Sem Fio', 150, '2026-08-01 10:00:00'), (3, 'Teclado Mecânico', 80, '2026-08-01 10:00:00'); INSERT INTO stg.Source_ProductInventory (ProductID, ProductName, Quantity, LastUpdated) VALUES (1, 'Notebook ThinkPad', 45, GETDATE()), -- Existing: Stock reduction (Requires UPDATE) (2, 'Mouse Sem Fio', 150, GETDATE()), -- Existing: No changes (4, 'Monitor Ultrawide', 30, GETDATE()), -- New (Requires INSERT) (5, 'Mesa com Ajuste de Altura', 15, GETDATE()); -- New (Requires INSERT) GO {% endcodeblock %}

4. The Stored Procedure with MERGE Logic

Now, let's create the Stored Procedure that will perform the synchronization. Notice how the logic flows naturally, handling each MATCHED and NOT MATCHED scenario.

{% codeblock "sql" %} USE DEVELOPMENT GO IF OBJECT_ID('proc_merge') IS NOT NULL BEGIN DROP PROCEDURE proc_merge END GO CREATE PROCEDURE proc_merge AS BEGIN SET NOCOUNT ON; MERGE INTO dbo.Target_ProductInventory AS target_inv USING stg.Source_ProductInventory AS source_inv ON (target_inv.ProductID = source_inv.ProductID) WHEN MATCHED AND target_inv.Quantity <> source_inv.Quantity THEN UPDATE SET target_inv.Quantity = source_inv.Quantity, target_inv.LastUpdated = source_inv.LastUpdated WHEN NOT MATCHED BY TARGET THEN INSERT (ProductID, ProductName, Quantity, LastUpdated) VALUES (source_inv.ProductID, source_inv.ProductName, source_inv.Quantity, source_inv.LastUpdated) WHEN NOT MATCHED BY SOURCE THEN DELETE ; END; GO EXEC proc_merge; {% endcodeblock %}
